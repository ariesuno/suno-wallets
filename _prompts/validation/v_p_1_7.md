
# Prompt de Validação 1.7v — B3 Transactions Fetch (v2)

## Objetivo
Validar se a implementação do Prompt 1.7 (B3 Transactions Fetch) segue corretamente os requisitos técnicos, de segurança e de arquitetura definidos.

## Checklist de Validação

### Estrutura e Arquitetura
- [ ] Código implementado no contexto **DDD** (`infrastructure` para cliente HTTP, `application` para casos de uso, `domain` para entidades e interfaces).
- [ ] Funções, classes e arquivos com **nomes em inglês**, mas comentários **em português-BR**.
- [ ] Cliente HTTP centralizado (`B3OfficialClient`) com:
  - [ ] mTLS configurado usando `.p12` (TLS 1.2+)
  - [ ] Método `makeRequest()` para centralizar headers, retries e logs.
  - [ ] Uso de variáveis de ambiente para credenciais e caminhos de certificado.
- [ ] Código dividido em arquivos pequenos e bem organizados (nunca > 300 linhas por arquivo).

### Boas Práticas e Segurança
- [ ] Máscara de CPF em todos os logs (`***CPF***`).
- [ ] Tokens e segredos **nunca** logados.
- [ ] Validação de parâmetros:
  - [ ] `CPF` obrigatório, exatamente **11 dígitos numéricos**.
  - [ ] `referenceStartDate` e `referenceEndDate` obrigatórios no formato **YYYY-MM-DD**.
  - [ ] `page` obrigatoriamente `>= 1`.
- [ ] Tratamento de erros:
  - [ ] `400` → parâmetro inválido.
  - [ ] `401/403` → token inválido ou sem permissão.
  - [ ] `429` → retry com backoff exponencial.
  - [ ] `5xx` → retry com jitter.

### Endpoint Implementado
- [ ] `GET /b3/transactions/{cpf}` com suporte a filtros `referenceStartDate`, `referenceEndDate` e `page`.
- [ ] Chamada ao endpoint oficial:
  ```
  GET {UrlData}/assets-trading/v2/equity/{documentNumber}?referenceStartDate=YYYY-MM-DD&referenceEndDate=YYYY-MM-DD&page=1
  ```
- [ ] Headers obrigatórios incluídos:
  - [ ] `Authorization: Bearer {access_token}`
  - [ ] `X-Investor-CPF: {cpf}`
  - [ ] `Content-Type: application/json`

### Testes e Documentação
- [ ] Testes unitários e de integração criados na **pasta correta** (`/tests/b3/transactions/`), com nome iniciando em `B3_Transactions_`.
- [ ] Coleções do **Postman** e **Bruno** atualizadas com exemplo real.
- [ ] Swagger atualizado com:
  - [ ] Descrição do endpoint.
  - [ ] Parâmetros e formatos de entrada.
  - [ ] Exemplos de resposta (200, 400, 401, 403, 429, 5xx).
- [ ] Observabilidade integrada (Prometheus/Grafana) com métricas:
  - [ ] Latência da requisição à B3.
  - [ ] Taxa de erro.
  - [ ] Quantidade de páginas processadas.

## Resultado Esperado
Ao executar um teste com CPF válido e datas dentro do período disponível, o sistema deve:
1. Autenticar via OAuth2 e mTLS.
2. Realizar a chamada para a B3 com parâmetros válidos.
3. Salvar **raw data** em tabela dedicada (`b3_raw_data_client`).
4. Retornar resposta formatada no endpoint.
5. Registrar métricas no sistema de observabilidade.
