# Prompt de Validação 1.8v — B3 Positions Fetch (v3)

## 🎯 Objetivo
Validar se a implementação do **Prompt 1.8 — B3 Positions Fetch (v3)** está 100% conforme os contratos oficiais da B3 e as diretrizes do projeto **suno-wallets** (DDD, segurança, observabilidade, testes e documentação).

---

## ✅ Checklist de Validação

### 1) Estrutura & Arquitetura (DDD)
- [ ] Código organizado em:
  - `src/Application/B3/positions/positions_service.go`
  - `src/Api/Controllers/B3/positions_controller.go`
  - `src/Shared/Validation/b3_input_validation.go` (reaproveitado)
  - `src/Shared/Dto/b3_positions_dto.go`
- [ ] Uso **obrigatório** do `B3OfficialClient` (1.6) — nenhuma chamada HTTP direta fora dele.
- [ ] **Nomes em inglês**; **comentários em pt-BR**; arquivos coesos (≤ ~300 linhas).
- [ ] Camadas respeitadas (Domain não conhece Infra; Application usa interfaces; Api orquestra).

### 2) Contrato & Validações (v3)
- [ ] Endpoint oficial usado corretamente:
  ```
  GET {UrlData}/position/v3/equities/investors/{documentNumber}?referenceStartDate=YYYY-MM-DD&referenceEndDate=YYYY-MM-DD&page=1
  ```
- [ ] **Headers obrigatórios** enviados em todas as chamadas:
  - `Authorization: Bearer {access_token}` (injetado pelo client 1.6)
  - `X-Investor-CPF: {cpf}`
  - `Content-Type: application/json`
- [ ] **Validações obrigatórias** no controller/service:
  - `cpf` com **11 dígitos numéricos** (erro **400** se inválido/ausente)
  - `start` e `end` no formato **YYYY-MM-DD** (**obrigatórios** em v3)
  - `page >= 1`
- [ ] Uso do método central `makeRequest(...)` do client (inclui mTLS, OAuth2, retry, timeout, logs, métricas).
- [ ] **Não persiste** no 1.8 (apenas preview). **Nenhum write em DB** nesta etapa.

### 3) Paginação & Fluxo
- [ ] Quando `fetchAllPages=true`, itera páginas até o fim (ou resposta vazia).
- [ ] Quando `fetchAllPages=false`, respeita `page` informado (com mínimo 1).
- [ ] Métrica/Log registra **quantidade de páginas** processadas.

### 4) Resiliência & Erros
- [ ] **Retry com backoff + jitter** para `429` e `5xx` (política do 1.6).
- [ ] **Timeout** por requisição e uso de `context.Context` em todos os métodos.
- [ ] Tratamento adequado de `400/401/403` com mensagens claras e instrução p/ renovar credenciais quando aplicável.
- [ ] **Nunca** logar tokens/segredos; **CPF mascarado** nos logs.

### 5) Observabilidade
- [ ] Logs estruturados (JSON) com campos: `tenantId`, `cpfMasked`, `endpoint`, `httpStatus`, `durationMs`, `retries`, `pages`.
- [ ] Métricas Prometheus:
  - Histograma de **latência** por endpoint
  - **Contadores** de sucesso/erro por status
  - **Contador** de páginas processadas (label `assetType`/`status`)
- [ ] Dashboards/queries preparados para acompanhar estas métricas (se aplicável ao 1.5).

### 6) Endpoint de Preview & Documentação
- [ ] Implementado `GET /b3/fetch/positions/preview?cpf=...&start=YYYY-MM-DD&end=YYYY-MM-DD&assetType=equity&page=1&fetchAllPages=true|false`
- [ ] **Swagger** atualizado (tag `B3 Data`), com parâmetros e exemplos de respostas (200, 400, 401, 403, 429, 5xx).
- [ ] **Postman** e **Bruno** atualizados com exemplo real (sanitizado).
- [ ] `docs/b3/positions.md` criado/atualizado com cURL e checklist de validações.

### 7) Testes
- [ ] **Unit** em `src/Tests/Unit/B3/positions_service_test.go` cobrindo:
  - Validação de `cpf`/datas/`page`
  - Montagem de URL e querystring
  - Paginação com `fetchAllPages=true`
  - Tratamento de 400/401/403/429/5xx
- [ ] **Integration** em `src/Tests/Integration/B3/positions_preview_test.go` (smoke com env real, se disponível).
- [ ] **Sem dados fake** sem autorização explícita. Em falta de dados reais, **pausar e solicitar instruções**.

---

## 📌 Resultado Esperado
Ao executar o preview com `cpf` e datas válidas:
1. O sistema autentica via OAuth2 (client 1.6) e usa mTLS (.p12).
2. A requisição é enviada com headers corretos e validações aplicadas.
3. Se `fetchAllPages=true`, todas as páginas são obtidas e **consolidadas** na resposta.
4. **Nada é persistido** em banco nesta etapa.
5. Logs e métricas são registrados (latência, status, retries, páginas).

Se **tudo** estiver conforme, responda:
```

```

Caso contrário, liste **exatamente** os itens em falta ou incorretos e proponha a correção objetiva para cada item.
