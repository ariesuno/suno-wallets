
# Prompt 1.4 — Infrastructure Layer (Camada de Infraestrutura)

Você é um desenvolvedor sênior especializado em arquitetura **DDD (Domain-Driven Design)**, **Clean Architecture** e **Go (Golang)**. 
Sua missão é implementar a **camada Infrastructure** do projeto `suno-core-wallets`, seguindo **fielmente** todas as diretrizes e padrões definidos no documento global do projeto.

---

## Objetivo da tarefa
Implementar a camada **Infrastructure** contendo todos os elementos necessários para integração com sistemas externos, persistência de dados e execução de tarefas assíncronas, garantindo **isolamento** e **adesão à arquitetura enterprise**.

---

## Estrutura esperada
A pasta `/infrastructure` deve conter, obrigatoriamente:

- `/repositories`
  - Implementações concretas das interfaces definidas no **Domain Layer**.
  - Repositórios para PostgreSQL, Redis, e demais fontes de dados.
  - Operações sempre recebendo **context.Context**.
- `/data`
  - Configuração do banco de dados (PostgreSQL) com suporte a **migrations**.
  - Configuração de conexões com Redis.
  - Pooling e parâmetros de performance.
- `/externalapis`
  - Implementações para consumo de APIs externas (B3, corretoras, etc.).
  - Uso de **interfaces** para permitir mocks em testes.
- `/backgroundjobs`
  - Workers e jobs assíncronos usando **Redis** e **Hangfire-like** libs (ex: asynq).
  - Logs e métricas em todos os jobs.
- `/observability`
  - Implementação de logs estruturados, métricas (Prometheus) e tracing (OpenTelemetry).
  - Padrões de logging definidos no projeto.
- `/config`
  - Carregamento de variáveis de ambiente.
  - Configurações globais (paths, chaves, etc.).

---

## Padrões obrigatórios
- **Nomenclatura** de arquivos, funções e variáveis sempre em inglês.
- **Comentários** sempre em **português do Brasil** explicando o que o código faz.
- **DDD e Clean Architecture** devem ser respeitados rigorosamente.
- Todos os acessos externos devem ter **timeouts configurados**.
- Nenhuma implementação concreta deve estar em `domain` ou `application`.
- Criar **testes unitários** para cada repositório e serviço implementado, salvos na pasta `/tests/infrastructure/...`.
- **Cobertura mínima** de 80% na camada de testes.

---

## Entregáveis
- Código da camada **Infrastructure** com toda a estrutura acima.
- Scripts de migrations no formato **.sql** e **.go** (quando aplicável).
- Configuração do Docker para PostgreSQL e Redis.
- Testes unitários completos.
- Documentação interna (`README.md`) explicando setup e uso.

---

## Observação final
Verifique se **TODOS** os arquivos estão corretamente organizados e que não existem implementações fora do local devido. 
Siga à risca a estrutura do projeto e mantenha **coerência arquitetural**.
