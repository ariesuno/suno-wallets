### ✅ Prompt 1.2 – Estrutura da Entidade `User`, com DDD, Multi-Tenant e Testes

Você deve atuar como um desenvolvedor sênior com experiência em arquitetura DDD, sistemas multi-tenant e projetos de alta performance. Com base no padrão usado no Prompt 1.1 (estrutura inicial do projeto), crie o módulo completo referente à **entidade `User`**, com base nas diretrizes a seguir:

### 🎯 Objetivo

Construir o módulo `users` seguindo o padrão DDD e multi-tenant, com:

1. **Entidade `User`** com os seguintes campos:
   - `id` (UUID)
   - `name` (string)
   - `email` (string)
   - `phone` (string)
   - `createdAt` (timestamp)
   - `updatedAt` (timestamp)
   - `tenantId` (UUID) → obrigatório para multi-tenant

2. **Interface de repositório** (`UserRepository`) com métodos básicos:
   - `Create`
   - `FindByID`
   - `FindByEmail`
   - `Update`
   - `Delete`

3. **Implementação em memória** do repositório (padrão `memory_repository.go`) para fins de teste.

4. Todos os comentários devem ser em **português do Brasil**, explicando claramente:
   - A função das interfaces
   - O papel da entidade
   - A lógica de cada método

5. Nome de **arquivos, funções e diretórios** sempre em **inglês**. Por exemplo:
   - `entity/user.go`
   - `repository/user_repository.go`
   - `repository/memory/user_memory_repository.go`

### 🧪 Testes

- Gere os testes unitários com Jest ou testing nativo do Go (caso Go seja a linguagem).
- Os testes devem ficar organizados na pasta:
  - `tests/users/`
- Crie ao menos um teste para:
   - Criar um usuário
   - Buscar por ID
   - Buscar por email
   - Atualizar um usuário
   - Deletar um usuário

### 📁 Estrutura Esperada

Exemplo de estrutura de pastas esperada no módulo `users`:

```
/src
  /domain
    /users
      entity/
        user.go
      repository/
        user_repository.go
        memory/
          user_memory_repository.go
  /tests
    /users
      user_repository_test.go
```

### 📌 Observações

- Todo módulo precisa ser **isolado e reutilizável**.
- O projeto segue arquitetura em camadas e princípios SOLID.
- A estrutura **multi-tenant é obrigatória**. Nunca esquecer do `tenantId`.
