## Prompt 1.1 — Setup inicial com DDD, estrutura de pastas e projeto

Quero que você crie a estrutura inicial do projeto usando a linguagem Go, com a stack definida previamente (Go, PostgreSQL, Redis, Swagger, Docker, etc.).

### Siga as diretrizes abaixo:

#### 1. Nomeação
- Use **inglês** para todos os nomes de arquivos, pastas, funções, structs, variáveis, endpoints e nomenclaturas de código em geral.
- Use **comentários em português (pt-BR)** para explicar o funcionamento de cada parte do código.

#### 2. Arquitetura (DDD)
- Utilize **Domain-Driven Design** com separação clara em pastas:
  - `domain/`: entidades, value objects, interfaces
  - `application/`: casos de uso, serviços de aplicação e DTOs
  - `infrastructure/`: repositórios concretos, APIs externas, jobs
  - `api/`: controllers, middlewares e rotas HTTP
  - `shared/`: helpers, constantes, validações, config, erros
  - `tests/`: testes unitários e de integração organizados em subpastas

#### 3. Configurações iniciais obrigatórias
- Configure o **Swagger** para documentação automática.
- Inclua **exportações para Postman e Bruno** (mesmo que ainda vazias).
- Crie um `README.md` com instruções básicas de execução local.
- Prepare o projeto para execução via **Docker** (`Dockerfile` e `docker-compose.yml`).
- Já inclua uma estrutura base de testes com **testify** e exemplo de teste simples em `tests/unit/example_test.go`.
- Aplique **multi-tenant desde o início**:
  - Adicione o campo `TenantID` nas entidades.
  - Configure middleware que injeta `TenantID` no contexto da request (ainda que de forma simulada).

#### 4. Estrutura de testes
- Todos os testes devem estar em `tests/`, organizados em:
  - `unit/`
  - `integration/`

#### 5. Boas práticas
- Evite arquivos com mais de 300 linhas — quebre se necessário.
- Estruture as dependências com modularização clara.
- Use `go mod` corretamente.
- Aplique boas práticas de código: injeção de dependência, interfaces, SRP, clean code.

> Esse prompt tem como objetivo gerar a fundação sólida do projeto com base em DDD, preparando o terreno para os próximos blocos de desenvolvimento.
