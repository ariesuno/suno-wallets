# Prompt 1.11 — Daily Sync Job (Incremental B3 fetch) — **suno-wallets**

Implemente o **job diário incremental** que consulta a B3 e atualiza o **RAW data** apenas quando houver **novidades** desde o último sincronismo do cliente. **Não** reprocessa o histórico completo; usa o **estado de sincronismo** por cliente. Ao concluir, marca clientes com novidades para **reprocessamento** (Fase 2), sem executá-lo aqui.

## 🎯 Objetivos
- Rodar **uma vez por dia** (configurável) e **incrementalmente** por cliente (CPF).
- Verificar **novas transações (v2)** e **novas posições (v3)** desde o `lastSyncAt` de cada cliente.
- **Persistir RAW** via serviços do **1.9** (idempotente), **apenas** do período novo.
- Marcar `needsReprocess=true` quando houver novos dados.
- Oferecer endpoints para **status**, **última sincronização** e **gatilho manual** (inclui `dryRun`).
- Observabilidade completa (métricas, logs) e **respeito a rate limit** da B3.

## 🗃️ Banco (migrations)
Crie migrations para o **estado de sincronismo** e eventos:

### 1) `b3_sync_state`
- `id` (uuid, pk)
- `tenant_id` (uuid, not null)
- `cpf` (varchar(11), not null)
- `is_active` (boolean, not null, default true) — se `false`, cliente é ignorado no agendamento
- **marcos por tipo de dado/versão**:
  - `last_tx_sync_at` (timestamptz, null) — última data/hora **transações v2** sincronizadas
  - `last_pos_sync_at` (timestamptz, null) — última data/hora **posições v3** sincronizadas
- **janelas verificadas** (controle de saúde):
  - `last_checked_at` (timestamptz, null)
  - `last_result` (varchar, null) — ex.: `OK`, `RATE_LIMIT`, `AUTH_ERROR`, `B3_ERROR`
  - `last_error` (text, null)
- **marcadores operacionais**:
  - `needs_reprocess` (boolean, not null, default false)
  - `failure_count` (int, not null, default 0)
- **constraints/índices**:
  - UNIQUE (`tenant_id`, `cpf`)
  - Índices por (`tenant_id`, `is_active`), (`tenant_id`, `needs_reprocess`)

### 2) `b3_sync_events` (opcional, auditoria/observabilidade)
- `id` (uuid, pk), `tenant_id`, `cpf`, `event_type` (`RUN`, `SUCCESS`, `ERROR`, `RATE_LIMIT`, etc.), `details` (jsonb), `created_at`

> **Importante**: o **RAW data não é excluído automaticamente**; purga é manual (LGPD/inatividade).

## ⚙️ Lógica do Job (alto nível)
1. **Seleção de alvo**: obter CPFs **ativos** por `tenantId` a partir de `b3_sync_state`.
2. **Cálculo de janela** por tipo:
   - `txWindow = (last_tx_sync_at, now]`
   - `posWindow = (last_pos_sync_at, now]`
   - Aplicar **normalização de datas** (ex.: usar **último dia útil** para posições se necessário). Tornar **configurável** no env.
3. **Ingestão incremental** (reuso do **1.9**):
   - Para cada tipo com janela > 0, chamar `POST /b3/fetch/historical` (via service) **somente nas datas novas** (janelas mensais internas).
   - Se retornar **novos RAWs**, marcar `needs_reprocess=true`.
4. **Atualização de estado**:
   - Em sucesso, atualizar `last_tx_sync_at` / `last_pos_sync_at` e `last_result=OK`.
   - Em erro, incrementar `failure_count`, registrar `last_error`/`last_result`, e **não** avançar o marco.
5. **Rate limit e resiliência**:
   - Respeitar política do 1.6 (retry/backoff + jitter para 429/5xx).
   - Limitar concorrência e distribuir CPFs (sharding) para evitar estouro de cota.
6. **Cache preventivo** (opcional): se uma janela **já foi checada** nas últimas `N` horas e **não** houve novidade, pular para reduzir custos (config `B3_SYNC_COLD_WINDOW_HOURS`).

## 🧭 Endpoints (Swagger: tag `B3 Sync`)
### `GET /b3/client/status?cpf=...`
- Retorna: `isActive`, `needsReprocess`, `lastTxSyncAt`, `lastPosSyncAt`, `lastCheckedAt`, `lastResult`, `failureCount`

### `GET /b3/client/last-sync?cpf=...`
- Retorna: datas/horas dos últimos marcos por **tipo de dado/versão** (v2/v3).

### `POST /b3/sync/run`
**Body (JSON):**
```json
{
  "scope": "single|tenant|all",
  "cpf": "00000000000",
  "dataTypes": ["transactions","positions"],
  "assetTypes": ["equity"],
  "force": false,
  "dryRun": false,
  "limit": 100,
  "concurrency": 5
}
```
**Comportamento:**
- `scope=single` → sincroniza apenas o CPF informado.
- `scope=tenant` → sincroniza CPFs ativos do tenant atual (limit/concurrency).
- `scope=all` → (apenas admin) todos os tenants (limit/concurrency).
- `force=true` → ignora marcos e reconsulta janela **inteira** (usa ingest 1.9 com `force=true`).
- `dryRun=true` → apenas plano; **não** salva RAW nem altera estado.

### `POST /b3/sync/dry-run`
- Igual ao `/run`, mas sempre `dryRun=true`.
