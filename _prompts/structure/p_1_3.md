
# Prompt 1.3 — Implementação da Camada de Domínio (Domain Layer)

Você é um desenvolvedor sênior seguindo padrões de arquitetura **DDD (Domain-Driven Design)**, trabalhando no projeto **sunowallets**.  
Sua tarefa agora é **implementar a camada de Domínio** conforme a arquitetura aprovada no Bloco 1 — Fase 1.

## Objetivo
Implementar todos os elementos da **Domain Layer**, garantindo que o código esteja desacoplado, bem tipado, testável e com **comentários em português**.

---

## Instruções Gerais
1. **Nomenclatura**:
   - Todos os nomes de arquivos, pastas, classes, structs, interfaces, variáveis e funções devem estar **em inglês**.
   - Comentários, documentação interna e descrições devem estar **em português**.
2. **Estrutura de Pastas** (dentro de `/src/Domain`):
   ```
   /Entities
   /ValueObjects
   /Enums
   /Interfaces
   ```
3. **Conteúdo obrigatório**:
   - `Entities/`: Entidades principais como `User`, `Portfolio`, `Asset`, `Transaction`, cada uma com **TenantID** e propriedades essenciais.
   - `ValueObjects/`: Itens como `Email`, `CPF`, `CNPJ`, `Money`, `DateRange`.
   - `Enums/`: Ex: `TransactionType`, `AssetType`, `CurrencyType`.
   - `Interfaces/`: Contratos que serão implementados nas camadas de aplicação ou infraestrutura, como `IUserRepository`, `IPortfolioRepository`, `ITransactionRepository`.

---

## Requisitos Técnicos
- Aplicar **DDD** e princípios de **SOLID**.
- Tipagem explícita em todas as funções e propriedades.
- Entidades devem ter **validações internas** (invariantes) para garantir consistência.
- `ValueObjects` devem ser **imutáveis**.
- **TenantID** deve estar presente em todas as entidades e interfaces relevantes para garantir o multi-tenant.
- Testes unitários devem ser criados para cada entidade e value object dentro de `/tests/unit/domain`.

---

## Checklist de Entrega
- [ ] Pastas criadas conforme estrutura definida.
- [ ] Todas as entidades, value objects, enums e interfaces implementadas.
- [ ] Comentários e documentação em português.
- [ ] Nomes de arquivos e código em inglês.
- [ ] Testes unitários cobrindo cenários de sucesso e erro.
- [ ] Código sem warnings ou erros de lint.
