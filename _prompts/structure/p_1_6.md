# Prompt 1.6 — B3 Official Client & Auth (OAuth2 + mTLS) — projeto **suno-wallets**

Implemente um **cliente oficial da B3** centralizado para consumo da API do Investidor (v3/v2), com **OAuth2** e **mTLS (.p12)**, seguindo DDD e as diretrizes do projeto (código em inglês, comentários em pt-BR, testes nas pastas certas, observabilidade e segurança).

## 🎯 Objetivo
Criar o módulo `B3OfficialClient` responsável por:
- Autenticação OAuth2 em **dois cenários**: **Client Credentials** (robôs/serviços) e **Authorization Code + PKCE (ALF)** (o consentimento é externo, mas deixe a **interface** preparada para receber/injetar tokens).
- Configurar **mTLS** via **certificado .p12** (TLS 1.2+ obrigatório).
- Centralizar **headers obrigatórios** e políticas de **retry/backoff**/**rate limit**/**timeouts**.
- Expor uma função central `makeRequest(ctx, method, path, query, cpf, needsAuth bool)` que aplique tudo acima.

## 🧱 Arquitetura (DDD)
Crie os seguintes artefatos nos caminhos sigeridos, mas use a melhor forma para o projeto:
- `src/Infrastructure/B3/client/b3_official_client.go` (http.Client com mTLS, OAuth2, retry/backoff, makeRequest)
- `src/Infrastructure/B3/client/auth/oauth_client_credentials.go` (fluxo Client Credentials)
- `src/Infrastructure/B3/client/auth/oauth_pkce.go` (interfaces/stubs para PKCE/ALF: exchange e refresh; permitir injeção de tokens válidos)
- `src/Infrastructure/B3/config/b3_config.go` (UrlData, ClientId, ClientSecret, CertP12Path, CertPassphrase, TimeoutSeconds, RetryPolicy)
- `src/Infrastructure/B3/errors/b3_errors.go` (erros padronizados)
- `src/Shared/Helpers/log.go` (logger estruturado com mascaramento de CPF e sem expor tokens)
- **Testes** em `src/Tests/Unit/B3` e `src/Tests/Integration/B3`

## 🔐 Autenticação OAuth2
- **Client Credentials**: obtenha `access_token` com `client_id`/`client_secret`; armazene expiração e renove antes de expirar.
- **PKCE/ALF**: mantenha interfaces para `exchange(code)` e `refresh(refresh_token)`; o consentimento (redirecionamento/callback) ocorre fora, mas este cliente deve **aceitar tokens injetados**.
- **Nunca** logue tokens, segredos ou passphrases.

## 🔒 mTLS (.p12) obrigatório
- Carregue `.p12` com `CertPassphrase` (env) e configure `tls.Config` (TLS 1.2+).
- Parâmetros via env: `B3_URL_DATA`, `B3_CLIENT_ID`, `B3_CLIENT_SECRET`, `B3_CERT_P12_PATH`, `B3_CERT_PASSPHRASE`, `B3_TIMEOUT_SECONDS`.
- Se necessário manter compatibilidade, aceite também `CertPath` legado (.cer).

## 📨 Headers obrigatórios (sempre)
- `Authorization: Bearer {access_token}`
- `X-Investor-CPF: {cpf}` → **obrigatório** nas chamadas de dados; validar **11 dígitos**. Erro 400 se ausente/ inválido.
- `Content-Type: application/json`

## 🔗 Contratos preparados (1.7/1.8 usarão)
- **Posições v3**: `GET {UrlData}/position/v3/equities/investors/{documentNumber}?referenceStartDate=YYYY-MM-DD&referenceEndDate=YYYY-MM-DD&page=1`
- **Transações v2**: `GET {UrlData}/assets-trading/v2/equity/{documentNumber}?referenceStartDate=YYYY-MM-DD&referenceEndDate=YYYY-MM-DD&page=1`
- **Validações**: datas no formato `YYYY-MM-DD`; `referenceStartDate`/`referenceEndDate` obrigatórios para v3 (posições); `page >= 1`.

## ♻️ Resiliência & Rate Limit
- **Retry com backoff exponencial + jitter** para 429 e 5xx.
- **Timeout** por requisição; uso de **context.Context** em todos os métodos.
- **Paginação**: helper para iterar páginas e consolidar resposta.
- **Mascarar CPF** nos logs (ex.: últimos 2 dígitos) e logar sempre `tenantId`, endpoint, status HTTP, duração e tentativas.

## 📊 Observabilidade
- Métricas Prometheus: latência por endpoint, sucesso/erro por status, contagem de retries.
- Logs estruturados (JSON) com os campos: `tenantId`, `endpoint`, `cpf_masked`, `httpStatus`, `durationMs`, `retries`.
- (Opcional) endpoint `/b3/health/auth` para verificar autenticação básica (sem expor segredos).
