## 🔐 Segurança & Multi-tenant
- Health e metrics **não** devem exigir `X-Tenant-Id` (são de plataforma).  
- **Nunca** logar tokens/segredos. Respostas **sem** valores sensíveis.
- `GET /b3/health/auth` somente em **ambiente controlado** (behind auth/rede interna) ou com **feature flag/env** (`OBS_ALLOW_B3_AUTH_HEALTH=true`).

## 🧪 Semântica dos Endpoints
### `GET /health/live`  — liveness
- **Retorna 200** se o processo está vivo e a thread principal responde.
- Corpo sugerido:
```json
{
  "status": "UP",
  "service": "suno-wallets",
  "version": "1.0.0",
  "commit": "abc1234",
  "startedAt": "2025-08-08T02:00:00Z",
  "uptimeSec": 12345
}
```

### `GET /health/ready` — readiness
- **Retorna 200** somente quando **DB** e **Redis** estão OK e **migrations** aplicadas.
- Corpo sugerido (exemplo):
```json
{
  "status": "UP",
  "components": {
    "db":    {"status": "UP", "latencyMs": 4},
    "redis": {"status": "UP", "latencyMs": 1},
    "queue": {"status": "UP", "latencyMs": 2}
  }
}
```

### `GET /health/details` — diagnóstico
- Inclui status dos componentes + counters básicos (ex.: `queueDepth`, `dbPoolInUse`, etc.).
- **Não** inclui segredos. **Não** exige tenant.
- Status agregado: `UP` | `DEGRADED` | `DOWN` com base nas dependências.

### `GET /b3/health/auth` — autenticação B3 (opcional/segura)
- Verifica **Client Credentials** (1.6) + montagem de **mTLS (.p12)** (sem chamada a endpoints de dados).
- Retorna 200 com `{ "auth": "OK" }` se token obtido e transport mTLS montado.
- **Não** logar token/segredo.

### `GET /metrics` — Prometheus
- Expor:
  - Histogram **HTTP latency** (por rota/status)
  - Counters `http_requests_total`, `http_errors_total`
  - `build_info{version,commit}` gauge
  - Métricas B3 (calls, latency, retries) já existentes (1.6/1.7/1.8/1.9/1.10/1.11)
- **Atenção a cardinalidade**: **não** usar `tenantId` como label em alto cardinality. Usar somente em logs.

## ⚙️ Implementação
- **Timeouts** de health-check por componente (ex.: 200–500ms).
- DB health: `SELECT 1` com contexto e deadline curto + verificação de versão de migration (se aplicável).
- Redis health: `PING` com deadline curto.
- Queue health (se houver): `PING`/depth.
- B3 Auth health: fluxo **Client Credentials** (1.6) com **transport mTLS** montado; descartar token após teste.
- **Logs estruturados** com `service`, `endpoint`, `status`, `durationMs`; **sem** segredos.
- Integrar ao **Swagger** (tag `Observability` e `B3 Data`).
