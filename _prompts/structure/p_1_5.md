# Prompt 1.5 - Configuração de Observabilidade e Monitoramento

## Objetivo
Implementar toda a infraestrutura de observabilidade e monitoramento do projeto **suno-wallets**, garantindo métricas, logs estruturados e rastreamento distribuído de forma alinhada a um padrão enterprise.

## Escopo
1. **Stack de Observabilidade**:
   - **Prometheus** para coleta de métricas.
   - **Grafana** para dashboards customizados.
   - **Loki** para centralização de logs.
   - **Tempo** para rastreamento distribuído (opcional, mas preparar a estrutura).

2. **Pontos de Monitoramento Obrigatórios**:
   - Latência média e p95/p99 de cada endpoint.
   - Contagem de erros por tipo (4xx, 5xx).
   - Métricas de chamadas à API da B3 (por endpoint da B3 e status HTTP).
   - Taxa de sucesso/falha dos jobs de sincronização diária.
   - Uso de CPU, memória e I/O (exportador do Prometheus).

3. **Padrões de Logs**:
   - **Formato**: JSON estruturado.
   - **Campos obrigatórios**:
     - timestamp
     - nível (info, warn, error)
     - serviço/módulo
     - trace_id e span_id (para rastreamento)
     - mensagem
     - detalhes (ex.: CPF mascarado, request_id, parâmetros relevantes)
   - **Mascarar informações sensíveis**: CPF, tokens, senhas.

4. **Alertas**:
   - Definir alertas no Prometheus para:
     - Latência acima de thresholds definidos.
     - Erros > 5% por endpoint em janelas de 5 minutos.
     - Falhas consecutivas em jobs de sincronização.

5. **Dashboards Grafana**:
   - Criar pelo menos:
     - **Visão Geral**: status de APIs, jobs e integrações.
     - **Integração B3**: métricas específicas de latência, erro e volume de chamadas.
     - **Infraestrutura**: CPU, memória, disco.

6. **Boas Práticas DevOps**:
   - Todos os nomes de arquivos e funções em inglês.
   - Comentários no código em português (pt-BR).
   - Estrutura DDD mantida.
   - Testes de integração para validar exposição de métricas no endpoint `/metrics`.
   - Coletar métricas internas via endpoint padrão do Prometheus.

7. **Pasta de Testes**:
   - Criar testes em `tests/observability`.
   - Prefixar nomes com `observability_`.

8. **Documentação**:
   - Adicionar instruções de configuração e acesso a dashboards no diretório `docs/observability`.
   - Salvar coleções no Bruno/Postman para endpoints de métricas e health.

---
**Resultado esperado**: Após este prompt, o projeto deve ter infraestrutura de observabilidade operando localmente, com métricas visíveis no Grafana, logs estruturados enviados ao Loki e alertas básicos configurados no Prometheus.
